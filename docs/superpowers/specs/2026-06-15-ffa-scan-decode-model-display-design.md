# Скан-декод + активная модель в UI + оверфлоу имени файла

**Дата:** 2026-06-15
**Ветка:** `ffa-scan-decode-model-display` (от `main`@`24182f4`)
**Тип:** баг-фикс (root cause) + мелкая фича + UI-фикс — один общий цикл, один PR.

## Контекст и проблема

Owner: «при добавлении нового шаблона поля не распознаются моделями» — создание шаблона
падает с `tpl_scan_fail_*` даже ПОСЛЕ деплоя платного last-resort хвоста (prod `24182f4`).
Плюс два сопутствующих пункта: (2) показывать, какая модель сейчас работает; (3) длинное
имя файла вылезает за рамки модалки.

### Root cause пункта 1 (подтверждён живой репродукцией)

Реальный прогон `proposeFields` против настоящего `Платежное_требование_образец.xlsx`
(тот же код-путь, что и `/api/templates`, реальный OpenRouter):

```
SHEETS: ["ПТ","Счет","График оплат","для вставки","Лист1"]
sheet "ПТ" lines=56:  B1: &#1055;&#1051;&#1040;&#1058;&#1045;&#1046;&#1053;&#1054;&#1045; ...
approx prompt body chars: 13717
ATTEMPTS: #1 gpt-oss → no fields; #2 nemotron-nano → ТАЙМАУТ; #6 gpt-4.1-nano → ТАЙМАУТ
RESULT after 47.0s: failure=nofields, fields=0
```

`decodeXml` в `lib/templates/xlsx-scan.ts` раскодирует только именованные сущности
(`&lt; &gt; &quot; &apos; &amp;`) и НЕ раскодирует **числовые символьные ссылки**
(`&#1055;` = `П`, `&#xHHHH;`). Этот образец (и Excel в общем случае) хранит кириллицу
именно числовыми ссылками. Последствия:

1. **Форма семантически нечитаема для модели** → `B1: &#1055;&#1051;&#1040;...` вместо
   `B1: ПЛАТЕЖНОЕ ТРЕБОВАНИЕ` → плохое/нулевое распознавание полей.
2. **Промпт раздут ~×3.6** (каждый кириллический символ → `&#NNNN;` ≈ 7 символов) →
   13.7k символов → модели виснут → **даже платный хвост таймаутит** в своём 12с-окне →
   `failure=nofields`. Это и есть «падает даже после деплоя».

Платный gpt-4.1-nano сам по себе здоров (зонд 4/4, 1.7–3.5с, валидный JSON, верные имена
листов) и архитектурно гарантированно вызывается — он таймаутит ИЗ-ЗА раздутого промпта,
не из-за биллинга/гео. Баллы OpenRouter в норме (`is_free_tier:false`, ~$6 кредитов).

**Доказательство фикса:** с раскодировкой числовых ссылок тот же образец → промпт
13717→**3829** символов, метки читаемы (`ПЛАТЕЖНОЕ ТРЕБОВАНИЕ`, `Автор заказа:`…), скан
вернул **`failure=null`, 20 валидных полей** с верными `ПТ!`-ячейками (платный хвост успел
ответить за свой бюджет).

## Изменения

### 1. Скан-декод (root-cause фикс)

`lib/templates/xlsx-scan.ts` → `decodeXml`: помимо именованных сущностей раскодировать
числовые символьные ссылки `&#DDDD;` (десятичные) и `&#xHHHH;` (шестнадцатеричные).

**Порядок важен:** числовые ссылки раскодировать ДО замены `&amp;`→`&`, иначе литеральный
текст `&amp;#1055;` (то есть строка «&#1055;») будет ошибочно превращён в `П`. Финальный
порядок: (a) `&#x…;` hex → (b) `&#…;` decimal → (c) `&lt; &gt; &quot; &apos;` → (d) `&amp;`
последним. `String.fromCodePoint` для значения ссылки.

`decodeXml` используется только в скан-пути (имена листов, sharedStrings, текст ячеек);
извлечение/парсинг счетов фикс не затрагивает — баг изолирован скан-путём.

### 2. Активная модель в UI (скан + извлечение)

- Новый общий хелпер `modelLabel(id)` в `lib/extract/llm/catalog.ts`: резолвит slug →
  человекочитаемое имя по `[...FREE_MODELS, PAID_LAST_RESORT]`, иначе возвращает сам slug.
  Единый источник правды.
- `components/wizard/Processing.tsx` (извлечение): заменить локальный `modelName`
  (ищет только в `FREE_MODELS`) на `modelLabel`, чтобы платная модель показывалась как
  «GPT-4.1 Nano (платная)», а не сырым слагом. Отображение текущей модели уже есть
  (`Пробуем {current}…`).
- `components/templates/NewTemplateModal.tsx` (скан): хранить текущую модель из события
  `attempt`, рендерить её label в busy-панели — строка `модель: <label>` над существующей
  `попытка i из n`. Резолв через `modelLabel`. Новый i18n-ключ для строки «модель: {name}»
  (или эквивалент); существующий `tpl_scan_model` («попытка {i} из {n}») сохраняется.

### 3. Оверфлоу имени файла

`NewTemplateModal.tsx`, кнопка выбора файла (показывает `file.name`): добавить
`whiteSpace: "nowrap", overflow: "hidden", textOverflow: "ellipsis", display: "block"`
чтобы длинное имя обрезалось с «…», не выходя за 480px-рамку модалки. Поля name/desc —
нативные `<input>`, обрезаются сами, их не трогаем.

## Тестирование (TDD)

- `xlsx-scan` / `decodeXml`: числовые десятичные, hex, именованные сущности и крайний
  случай `&amp;#NNNN;` (остаётся литералом). Юнит на `sheetTexts` с образцом-фикстурой,
  содержащей числовые ссылки → ожидаем читаемую кириллицу.
- `catalog` / `modelLabel`: free-slug → имя, paid-slug → «…(платная)», unknown → сам slug.
- UI: label текущей модели в модалке и обрезка имени файла — в стиле существующих
  компонентных тестов.
- Полный прогон Vitest + `tsc` + `next build` зелёные перед мерджем.

## Non-goals

- Не трогаем порядок/таймауты свободного пула и не добавляем leniency для `Лист!`-плейсхолдера
  (декод даёт верные имена листов; платный хвост закрывает вис свободных моделей).
- Не обрезаем не-форменные листы (`для вставки`, `Лист1`) из скана — не требуется для
  фикса; возможный отдельный follow-up.
- Глобального «статус-бара» в сайдбаре не вводим — модель показывается в местах прогресса
  (модалка скана, экран Processing).
