# Презентабельный гостевой мастер — design

**Дата:** 2026-06-25
**Контекст:** [[ffa-web-project]] · гостевой доступ (merge `0e8b8ab`)

## Проблема

На публичной странице `/` (`GuestShell`) мастер `WizardModal` рендерится в режиме
`embedded`, но сохраняет модальную обвязку:

- Крестик `×` в шапке (`WizardModal.tsx:100`) и «Назад» на шаге 0
  (`WizardModal.tsx:129`) оба вызывают `onClose`, который для гостя —
  `setKey(k+1)`, т.е. перемонтирование/сброс мастера. Закрывать нечего (мастер и
  есть страница) → кнопки выглядят сломанными.
- Тяжёлая тень карточки (`0 24px 80px rgba(0,0,0,.35)`) читается как зависшее
  модальное окно посреди пустой страницы → «не презентабельно».
- Финальный шаг (`DoneStep`) показывает кнопку `open_dash` («В рабочую область»),
  но гостю некуда идти.

## Цель

Для гостя мастер выглядит как встроенная рабочая панель с приветственным hero,
без нерабочих кнопок. Любая видимая кнопка работает.

## Решение

Поведение гейтится на уже существующих флагах `embedded` (визуальный режим, сейчас
используется ТОЛЬКО `GuestShell`) и `GuestContext.guest`. Кабинетная модалка
(overlay + `×` + back) не затрагивается.

### 1. `components/wizard/WizardModal.tsx`

- Крестик `×` в шапке: рендерить только когда `!embedded`.
- Футер, шаг 0: кнопку «Назад» рендерить только когда `!embedded`. На шаге 0
  остаётся одна кнопка «Начать обработку», прижатая вправо.
- Шаг 2: «Назад» (→ шаг 1) сохраняется как реальная навигация — без изменений.
- Тень карточки в `embedded` смягчить до `0 8px 32px rgba(0,0,0,.18)`.

Логика футера для шага 0 в `embedded`: левый слот пустой (или отсутствует),
правый слот — «Начать обработку». Раскладка `justify-content: space-between`
сохраняется; пустой левый слот (`<span />`) удерживает кнопку справа.

### 2. `components/wizard/DoneStep.tsx`

- `guest` уже доступен через `useContext(GuestContext)`.
- Нижняя кнопка: если `guest` → текст `guest_again` («Заполнить ещё документ»);
  иначе → `open_dash` (как сейчас). `onClick={onClose}` не меняется — для гостя он
  и так перемонтирует свежий мастер (= «заполнить ещё»).

### 3. `components/guest/GuestShell.tsx`

В `GuestWizard`, над `<WizardModal>`, добавить hero-блок:

- Заголовок: `guest_hero_h`.
- Подзаголовок: `guest_hero_sub`.
- Тонкая строка-доверие: `guest_hero_note`.

Hero центрируется по той же ширине, что и карточка мастера
(`min(1080px, 100%)`), с разумным верхним отступом. Состояние загрузки
(`guest_loading`) и логика `key`-сброса не меняются.

### 4. `lib/seed/pt.ts` — новые ключи `STR` (ru/en)

| key | ru | en |
|-----|----|----|
| `guest_hero_h` | Заполните документ за минуту | Fill a document in a minute |
| `guest_hero_sub` | Загрузите счёт или договор — AI извлечёт данные и заполнит бланк | Upload an invoice or contract — AI extracts the data and fills the form |
| `guest_hero_note` | без регистрации · бесплатные модели | no signup · free models |
| `guest_again` | Заполнить ещё документ | Fill another document |

## Поведение «закрытия» после изменений

В гостевом мастере нет крестика и нет «Назад» на шаге 0. Единственный путь начать
заново — кнопка «Заполнить ещё документ» на финальном шаге (перемонтирует свежий
мастер через существующий `onClose`). Это намеренное, презентабельное поведение.

## Вне scope

- Рефактор `WizardModal` на отдельный prop вместо `embedded` (сейчас `embedded`
  однозначно = гость, переиспользуем).
- Изменение шага 2 «Назад» / перезапуска извлечения.
- Любые изменения кабинетной (полно-юзерской) модалки.

## Проверка

- `tsc` чисто, `eslint` без новых ошибок.
- Vitest зелёный (изменения — презентационные; при наличии теста на гостевую
  карточку обновить).
- Ручной смоук на `/`: шаг 0 без `×` и без «Назад», только «Начать»; финал у гостя
  показывает «Заполнить ещё документ» и перезапускает мастер.
